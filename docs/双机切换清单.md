# MAX × VideoUse 双机切换清单

## 新电脑首次初始化

1. 登录同一 Codex 账号，并安装与旧电脑兼容的 Node.js、Git、VideoUse 运行环境。
2. 克隆 MAX 视频项目私有仓库；不要复制旧电脑的 `node_modules`、`.env` 或缓存。
3. 在 NAS 挂载个人知识库、素材库和交付库。
4. 从 `config/nas-paths.example.json` 创建本机的 `config/nas-paths.json`。
5. 在项目根目录安装依赖，并单独配置本机所需的 VideoUse 凭据；不得复制或提交旧机器的 Key。
6. 打开一个已有项目时，从 NAS 的实际路径重新链接原片，确认指纹、时长、方向和播放正常。

## 从电脑 A 切到电脑 B

1. 在 A 保存工作台版本，结束编辑和导出任务。
2. 将需要保留的文本决策、规则、Skill 和代码提交并推送到私有 GitHub 仓库。
3. 确认 NAS 中的原片与交付文件已完成写入，再卸载或停止使用 A 上的项目。
4. 在 B 挂载 NAS，拉取 GitHub 最新提交。
5. 从 B 的 NAS 路径打开项目，重新授权和链接源素材。
6. 先播放开头、中间切点和结尾，确认工作台加载的是目标 EDL/版本，再继续编辑。

## 日常规则

- 同一个项目一次只在一台电脑上编辑。
- Git 只同步规则、代码和可审计文本；NAS 同步媒体与交付。
- 不把 `working-draft.json`、`events.jsonl`、代理和缓存当作跨机器实时协作文件。
- 每次切换前后都检查 `git status`，避免未提交的规则或决策留在另一台电脑。
- 当素材路径、文件指纹或代理状态异常时，停止编辑，重新链接源素材；不要把旧预览片当新的 EDL 母版。

## 故障回退

如果 B 上的工作台打不开旧项目：保留其报错和当前草稿，不覆盖 NAS 原片；回到已确认的 Git 提交，从 NAS 重新选择最终 EDL 与源素材，并重新生成本机代理。历史工作台版本只读，恢复时应生成新的工作草稿。
