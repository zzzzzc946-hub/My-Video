# MAX × VideoUse 双机切换清单

## 新电脑首次初始化

1. 登录同一 Codex 账号，安装 Node.js、Git 与 VideoUse；不复制旧电脑的 `node_modules`、`.env` 或缓存。
2. 克隆私有仓库并切换到 `codex/two-computer-sync`，执行 `git pull origin codex/two-computer-sync`。
3. 创建本机 `CHEN BRAIN`、`MAX视频本地资料/原片` 与 `MAX视频本地资料/交付` 的本地工作副本；NAS 仅作为阶段镜像。
4. 从 `config/nas-paths.example.json` 创建本机忽略的 `config/nas-paths.json`，填写**本地**路径。
5. 单独配置本机 VideoUse 凭据；不得复制或提交另一台电脑的 Key。
6. 同步规则、Skill、项目文档和本条视频所需媒体后，才在本地重新链接源素材并核验指纹、时长、方向和播放。

## 从电脑 A 切到电脑 B（硬门槛）

1. A 停止该视频的编辑、导出和工作台写入，保存可审阅版本。
2. A 提交并推送 Skill、项目文档、模板和文本决策到 `codex/two-computer-sync`。
3. 对本地 `CHEN BRAIN` 与 NAS 执行阶段同步：单端变更可复制；双端同一文件变更为 `REVIEW`，必须先由决策中枢合并。
4. 按项目目录同步需要的原片与交付；不覆盖原始 EDL、历史交付、缓存、代理或 `.env`。
5. B 拉取 `codex/two-computer-sync`，再同步到其本地知识库和本地媒体副本。
6. B 从本地路径重新选择并授权源素材，播放开头、关键切点和结尾，确认目标 EDL/版本后才继续编辑。

存在未解决 `REVIEW`、未推送 Git 变更或同步未完成时，不得切换同一视频的编辑电脑。

## 日常规则

- 同一个项目、规则文件或工作台草稿不得同时在两台电脑编辑。
- Git 同步 Skill、代码、模板和可审计文本；NAS 只做阶段镜像与媒体备份。
- 规则正文只由决策中枢写入；每条视频窗口只提交反馈和单条日志，不自行改写全局规则。
- 不把 `working-draft.json`、`events.jsonl`、代理和缓存当作跨机器实时协作文件。
- 每次切换前后检查 `git status` 和是否存在 `REVIEW`。

## 故障回退

若 B 无法打开旧项目：保留报错和本地草稿，不覆盖 NAS 原片；回到已确认 Git 提交，从本地媒体副本重新选择最终 EDL 与源素材，并重新生成代理。历史工作台版本只读，恢复时生成新的本地工作草稿。
