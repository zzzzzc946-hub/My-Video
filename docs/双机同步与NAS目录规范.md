# MAX × VideoUse 双机同步与 NAS 目录规范

## 本地优先与单一权威

日常工作只在当前电脑本地进行。NAS 不是实时工作盘，而是用户明确要求、规则确认后或切换电脑前才更新的阶段镜像。

| 内容 | 日常工作真源 | 同步目标 | 硬规则 |
| --- | --- | --- | --- |
| MAX 00–07 | 当前决策中枢的本地 `CHEN BRAIN` | NAS `CHEN BRAIN` | 同一时刻只允许决策中枢修改规则；另一台电脑只读或记录单条反馈。 |
| Skill、项目文档、模板、源码 | Git `codex/two-computer-sync` | GitHub 私有仓库 | 先拉取、后编辑、完成即提交推送；不得在 `main` 工作。 |
| 原片与交付 | 当前电脑本地 `MAX视频本地资料` | NAS 媒体／归档目录 | 每条视频一次只在一台电脑编辑。 |
| 缓存、代理、`node_modules`、`.env` | 当前电脑 | 不同步 | 可重建，不进入 Git 或 NAS。 |

本机本地工作目录：

```text
/Users/chen.zip/Documents/
├── CHEN BRAIN/
└── Codex/MAX视频本地资料/
    ├── 原片/
    └── 交付/
```

使用忽略的 `config/nas-paths.json` 记录这三个**本地工作路径**。NAS 的实际挂载路径只用于阶段同步，不写入可提交配置。

## 规则与配置同步协议

只在以下时机同步：用户明确说“同步配置和规则到 NAS”、规则确认后、或切换电脑前。

1. 停止同一视频的编辑、导出和工作台写入。
2. 检查本地、NAS 与 Git 分支 `codex/two-computer-sync` 的状态。
3. 对规则与配置逐文件比较：只有一端变化时才复制；两端同一文件都有变化时，立即标记 `REVIEW` 并停止该文件同步。
4. `REVIEW` 只能由决策中枢合并；不得以任一电脑或 NAS 的版本静默覆盖另一端。
5. 同步规则、Skill、项目文档和明确要同步的配置；不覆盖原片、原始 EDL、历史交付、缓存、代理、日志、`.env` 或密钥。
6. 记录本次同步范围、来源、目标与未解决的 `REVIEW`；存在未解决冲突时不得切换该视频的编辑电脑。

## VideoUse 工作台迁移边界

工作台记录的源素材路径、文件指纹、时间线和草稿只在本机有效。换电脑时：

1. 在 B 上先拉取 `codex/two-computer-sync`。
2. 完成本地知识库和需要的媒体副本同步；任何冲突先解决 `REVIEW`。
3. 在 B 的本地路径重新选择并授权源素材，核对指纹、时长、方向和播放。
4. 重新生成本机代理后才开始编辑。

旧电脑的绝对路径、缓存和工作台草稿不能直接作为 B 的工作母版。

## 并发与安全边界

- 同一规则文件、同一 VideoUse 项目、同一 `working-draft.json` 或 `events.jsonl` 不得同时在两台电脑编辑。
- 原片、交付片和客户资料不进入 GitHub。
- `.env` 与 API Key 只留本机；第二台电脑独立配置。
- 缓存累计达到 10GB 时仅提醒人工清理，不自动删除。
