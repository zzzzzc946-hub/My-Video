# MAX × VideoUse 双机同步与 NAS 目录规范

## 本地优先与单一权威

日常工作只在当前电脑本地进行。NAS 不是实时工作盘，而是用户明确要求、规则确认后或切换电脑前才更新的阶段镜像。

| 内容 | 日常工作真源 | 同步目标 | 硬规则 |
| --- | --- | --- | --- |
| MAX 00–07 与规则候选 | GitHub `zzzzzc946-hub/CHEN-BRAIN` 的 `main` | 两台电脑本地 clone、NAS 单向镜像 | 当前这台电脑是唯一决策中枢；另一台电脑只能新增候选，不能改正式00–07。 |
| Skill、项目文档、模板、源码 | Git `codex/two-computer-sync` | GitHub 私有仓库 | 先拉取、后编辑、完成即提交推送；不得在 `main` 工作。 |
| 原片与交付 | 当前电脑本地 `MAX视频本地资料` | NAS 媒体／归档目录 | 每条视频一次只在一台电脑编辑。 |
| 缓存、代理、`node_modules`、`.env` | 当前电脑 | 不同步 | 可重建，不进入 Git 或 NAS。 |

本机本地工作目录：

```text
/Users/chen.zip/Documents/
├── CHEN BRAIN/
└── Codex/MAX视频本地资料/
    ├── 原片/
    └── 交付/
```

使用忽略的 `config/nas-paths.json` 记录这三个**本地工作路径**。本地 `CHEN BRAIN` 必须是 `CHEN-BRAIN` 的 Git 工作副本；NAS 的实际挂载路径只用于 Git 已确认版本的单向镜像，不写入可提交配置。

## 规则与配置同步协议

正式规则和候选通过 GitHub 同步；NAS 只在用户明确说“同步配置和规则到 NAS”、规则确认后、或备份时接收单向镜像。

1. 开始视频前在本机 `CHEN-BRAIN` 执行 `git pull --ff-only`，把 `git rev-parse HEAD` 写入本条任务记录；任务中固定该规则快照。
2. 另一台电脑结束视频后只在 `03｜CHEN操盘手系统/03｜MAX剪辑系统/08｜规则候选收件箱/open/` 新增独立候选并提交推送；不得改正式00–07或NAS正文。
3. 当前电脑的决策中枢拉取候选、检索03／06／Skill、去重并裁决；只有它可更新正式规则与 processed 状态。
4. 正式规则推送被拒绝时立即停止、快进拉取并重新检索裁决；禁止强推或以本地版本覆盖远端。
5. NAS 仅镜像已经推送的 `CHEN-BRAIN/main` 提交，并记录来源 SHA 与文件哈希。NAS 手工改动或 SHA 不一致时标记 `REVIEW`，不得反向写入 Git。
6. Git 继续同步 Skill、项目文档和代码；不把原片、原始 EDL、历史交付、缓存、代理、日志、`.env` 或密钥放入任一同步流。

## VideoUse 工作台迁移边界

工作台记录的源素材路径、文件指纹、时间线和草稿只在本机有效。换电脑时：

1. 在 B 上先拉取 `codex/two-computer-sync`，并在本地 `CHEN-BRAIN` 快进拉取 `main`。
2. 完成本地知识库和需要的媒体副本同步；B 只创建规则候选，任何正式规则冲突均交由当前电脑的决策中枢处理。
3. 在 B 的本地路径重新选择并授权源素材，核对指纹、时长、方向和播放。
4. 重新生成本机代理后才开始编辑。

旧电脑的绝对路径、缓存和工作台草稿不能直接作为 B 的工作母版。

## 并发与安全边界

- 同一正式规则文件、同一 VideoUse 项目、同一 `working-draft.json` 或 `events.jsonl` 不得同时在两台电脑编辑；不同视频可并行新增独立规则候选。
- 原片、交付片和客户资料不进入 GitHub。
- `.env` 与 API Key 只留本机；第二台电脑独立配置。
- 缓存累计达到 10GB 时仅提醒人工清理，不自动删除。
