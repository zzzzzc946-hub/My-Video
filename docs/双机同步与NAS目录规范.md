# MAX × VideoUse 双机同步与 NAS 目录规范

## 单一真源

GitHub 私有仓库是规则、Skill、工作台源码、模板和文本决策的单一真源。NAS 是个人知识库、原片、项目素材、预览与最终交付的共享存储。每台电脑只保留本地运行依赖和可重建缓存。

| 存储位置 | 保存内容 | 不保存内容 |
| --- | --- | --- |
| GitHub 私有仓库 | `AGENTS.md`、`docs/`、`references/`、`iteration/`、`templates/`、MAX Skill、工作台源码、经确认可提交的文本 EDL/决策/清单 | API Key、`.env`、原片、预览片、代理、渲染缓存、客户隐私素材 |
| NAS | 个人知识库、原片、可长期保留素材、项目交付片、必要的历史项目归档 | `node_modules`、代理、缩略图、临时渲染文件、运行日志 |
| 当前电脑 | `node_modules`、代理、缩略图、转写缓存、临时渲染、当前会话草稿 | 唯一的规则副本、唯一的原片或唯一交付片 |

## 推荐 NAS 目录

```text
<NAS>/
├── CHEN BRAIN/                 # 个人知识库，只读作为 MAX 上层输入
├── MAX视频素材库/
│   ├── 原片/
│   └── 项目素材/
└── MAX视频交付/
    ├── 最终交付/
    └── 历史归档/
```

使用 `config/nas-paths.json` 记录本机挂载位置。配置文件不进入 Git，不得写入任何凭据。

## VideoUse 工作台的迁移边界

工作台项目会记录源素材路径、文件指纹、时间线、草稿和版本。源素材的真实路径与指纹以当前打开请求为准，旧电脑写入的绝对路径不能直接被新电脑信任。

因此，换电脑时：

1. 在新电脑挂载 NAS。
2. 拉取 GitHub 中的规则、源码和文本记录。
3. 从新电脑的实际 NAS 路径打开 VideoUse 项目或最终 EDL。
4. 在工作台内显式授权并重新链接每个源素材。
5. 检查时长、指纹、代理和播放器，再开始任何编辑。

这不是缺陷，而是为了避免旧路径或被替换的媒体被静默当成同一个源文件。

## 并发规则

同一时刻只允许一台电脑编辑同一个 VideoUse 项目的 `working-draft.json`、`events.jsonl` 或版本快照。另一台电脑可以只读审阅，但不得同时改时间线或导出。

完成当前电脑的工作后，先保存工作台版本和需要同步的文本决策，再提交并推送 Git；另一台电脑拉取成功后再开始编辑。不要依赖 NAS 共享目录来合并两个工作台草稿。

## 安全边界

- `.env` 与所有 API Key 只留在本机；第二台电脑独立配置。
- 原片、交付片和客户资料不进入 GitHub。
- 个人知识库挂载后按上层规则只读；没有明确授权，不从视频工程修改其内容。
- 缓存累计达到 10GB 时仅提醒人工清理，不自动删除。
