# 视频项目剪辑上层 Agent：理解文档

## 这套系统在训练什么

本项目训练的核心不是某个剪辑软件，也不是一个只会按静音切片的自动化脚本，而是一个能够依据特定人物与账号目标做判断的**剪辑师 Agent**。

剪辑师的价值在于理解：这句话该不该留、哪一段应该前置、哪些例子可以整段删除、怎样保持原意不被剪坏、以及怎样把用户反馈变成下一条视频更准确的判断。

## 三层结构

```text
上层剪辑师 Agent
├── 人物专属剪辑 Skill
│   ├── MAX 粗剪 Skill（当前训练对象）
│   └── CHEN 剪辑 Skill（未来独立训练）
├── 工具适配层
│   ├── ChatCut
│   ├── VideoUse
│   └── 其他未来工具
└── 单条视频任务
    ├── 素材与目标
    ├── 临时任务卡
    └── 本条选定的执行工具
```

### 1. 人物专属剪辑 Skill：决定“怎么剪”

每一个人物有一套独立的剪辑判断系统，包含：

- 人物边界、价值观、表达禁区；
- 账号定位、目标受众和内容目标；
- 稳定的粗剪判断规则；
- 自有案例、外部参考、历史反馈与校准；
- 单条视频允许提出的临时要求。

**MAX 粗剪 Skill 是当前唯一正在打磨的人物 Skill。** 用户提供的 MAX 案例、逐字稿、偏好、反例和成片反馈，只能进入 MAX 的规则、案例或校准体系，不能擅自泛化为 CHEN 或其他人的规则。

未来新增 CHEN 剪辑 Skill 时，必须建立独立的规则、案例库、反馈库和任务卡；MAX 与 CHEN 的内容判断不得互相覆盖。

### 2. 工具适配层：决定“用什么执行”

ChatCut、VideoUse、剪映及未来工具都是执行工具，不定义人物风格或剪辑判断。

上层剪辑师先产出工具无关的剪辑决定：结构、保留/删除/移动片段、时间码、字幕要求、版本、质量检查点与留存要求；再将这些决定翻译为所选工具的时间线操作、EDL、导出设置或审核清单。

每条视频开始时必须明确选定执行工具。未指定时默认 VideoUse；选定 ChatCut 时，只走 ChatCut 的转写、时间线和导出；选定 VideoUse 时，才启动本地转写、EDL、渲染与缓存。没有被选定的工具不得因为“已安装”而自动运行。

工具可随时替换或新增；只要能承接上述剪辑决定、输出可核对的版本和过程记录，就能接入，而不影响人物专属 Skill。

### 3. 单条视频任务：决定“这条怎么交付”

单条任务只补充本条素材、发布目标、时长、临时偏好、必须保留/删除内容和选定工具。它不能突破人物边界、账号定位、稳定粗剪规则和语义保真要求。

## 通用粗剪工作流

1. 读取对应人物的规则系统与本条任务卡。
2. 选定执行工具，并记录原因。
3. 导入素材，取得可核对的转写、时间码和必要画面信息。
4. 按人物专属 Skill 做内容重构与表达精修判断。
5. 输出可审阅的剪辑决策：结构、时间码、删改理由、预计时长、风险与待确认项。
6. 按人物专属授权在选定工具中执行；MAX 自2026-10-17起默认直接执行、自审并交付最终成片，无须常规策略确认；保存可回退版本。
7. 检查逻辑、语义、音画同步、开头、结尾、切口与可播放性。
8. 留存决策和用户反馈；稳定反馈进入对应人物的校准体系。

## 留存与清理

过程文档是长期记忆，执行工具产生的预览、缓存、检查图和转写缓存属于可重建草稿。每完成一条视频时统计一次累计占用；达到 10GB 时提醒用户手动清理。系统不得自动删除原片、最终交付或草稿。

## 更新原则

- 用户对某个人物剪辑判断的明确反馈，更新到该人物对应的规则、案例或校准体系。
- 工具变化只更新工具适配层，不重写人物剪辑判断。
- 新人物必须新建独立 Skill，不从 MAX 直接复制结论。
- 规则冲突不能自行模糊合并，必须明确报告冲突来源与待确认点。
