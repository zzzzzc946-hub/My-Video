# VideoUse 工作台同步包设计

## 目标

将主电脑上已验证的 VideoUse 工作台与快速最终导出能力整理为一个可运行的 Git 同步包，使另一台电脑检出 `codex/two-computer-sync` 后可使用同一套工作台与 MAX 粗剪路由。

## 范围

同步包仅包含：

- `workbench/` 中运行工作台、任务状态、导出路由、数据模型与网页界面所需的源文件；
- 与这些能力对应的测试；
- MAX 粗剪 Skill 与工作台契约文档。

不包含 NAS 原片、个人知识库、制作记录、原始或历史 EDL、渲染缓存、最终成片，以及与工作台运行无关的设计草稿。

## 架构与行为

工作台保留原有的兼容导出。单一源视频、只删留或调序、无字幕、调色、外部素材或包装且保持源帧率时，最终候选通过工作台的最终视频导出走快速路径：一次 FFmpeg filtergraph 合成，使用 macOS `h264_videotoolbox` 产生 1080P、源帧率、标准质量 MP4。其余情况自动回退兼容导出。

快速路径不改变内容判断、词级切点、EDL、30ms 音频淡入淡出或五维切点审查。NAS 源片仍先复制到本机本条任务目录，再进行转写、检查与渲染。

## 打包与验证

从主电脑的未提交改动中逐文件迁入隔离工作区，不能整体覆盖目录。对工作台相关测试运行最小验证，并做 TypeScript/构建检查（若项目已有对应命令）。通过后只提交本同步包并推送 `origin/codex/two-computer-sync`。

另一台电脑完成 GitHub 授权后检出该分支、配置被忽略的 NAS 本地路径、启动工作台，并以本地测试项目验证快速导出是否可用；不得在验证阶段修改 NAS 原片或产生真实渲染。

## 错误处理

若硬件编码、单源条件或导出参数任一条件不成立，工作台必须显示或记录兼容路径而非假称快速导出。若本地副本校验失败，不开始转写或渲染。工作台启动、归档或同步超过 60 秒不应阻塞已验证候选的交付。

## 成功标准

- 共享分支包含完整工作台实现、测试、Skill 与契约，且不夹带用户素材或历史产物。
- 快速通道由工作台而非全局 `render.py` 执行，并能被针对性测试覆盖。
- 另一台电脑无需复制主电脑目录，即可在其 NAS 配置下启动和验证工作台。
