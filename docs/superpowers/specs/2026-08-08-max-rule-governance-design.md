# MAX 剪辑规则写入闸门设计

**状态：** 待用户复核  
**日期：** 2026-08-08  
**范围：** MAX 真人口播粗剪的反馈归档、校准、稳定规则升级与 Skill 同步；不涉及视频执行、渲染或工作台功能。

## 目标

防止每条视频的复盘机械追加为长期规则，导致重复、冲突、规则漂移和检索污染。任何迭代先经过检索、比对和裁决，再以最小信息写入唯一合适的位置。

## 唯一来源与职责

| 位置 | 唯一职责 | 禁止内容 |
| --- | --- | --- |
| `03｜MAX粗剪判断标准` | 已确认、可跨视频执行的稳定规则正文 | 单条视频过程、重复证据、未经确认的偏好 |
| `06｜MAX剪辑反馈与校准库` | 反馈证据、例外、关联案例、等级与升级状态 | 重复抄写03规则、长篇逐视频复盘 |
| `max-jianji-skill` | 工具无关的执行步骤、检索顺序、写入闸门 | 再造一份MAX判断库 |
| 单条视频 `rough-cut-log` / 决策报告 | 原始取舍、时间码、版本与本条经验 | 自动升级为长期规则 |

## 强制写入闸门

每条视频结束后，只要拟写入长期知识，必须依次：

1. 归类反馈：人物/受众边界、具体粗剪判断、技术执行、单条偏好或包装偏好。
2. 定向检索：相关 `03` 稳定规则、`06` 同类错误编码与条目、MAX Skill 的执行约束；必要时检索关联案例。
3. 对比裁决：判断新反馈与现有材料是同义、补充、例外、冲突或全新问题。
4. 选择唯一写入动作。
5. 写入“裁决摘要”，并引用已有编号或规则位置。

不得跳过检索直接追加；不得以“用户刚反馈”为理由把一次性取舍写成长期规则。

## 五种唯一写入动作

| 裁决 | 条件 | 写入位置 |
| --- | --- | --- |
| 不写入 | 现有规则已充分覆盖，本次只是执行失败或转写/素材问题 | 单条日志；必要时记为执行问题 |
| 合并证据 | 与现有 CAL 是同一判断问题 | 更新原 CAL 的案例、证据计数或例外，不新建条目 |
| 新建 F1 | 新问题，但证据仅来自当前视频 | 06 的极简 F1 条目 |
| 修订/升级 | 已达 F3 条件，或用户明确指定为全局原则；F5 红线立即生效 | 03 更新正文；06 标记其证据与替代规则 |
| 本条经验 | 取舍只服务当前主题、素材、时长或发布要求 | 单条日志，不进入06、03或Skill |

## 冲突裁决

- 新反馈与01/02/03硬边界冲突：不静默写入，标记 `REVIEW`，由用户裁决。
- 与既有稳定规则同义：合并证据，不增加近义表述。
- 比既有规则更窄：作为既有规则的例外条件写入原 CAL，不新建并列规则。
- 规则方向相反但证据不足：保留为本条经验或 F1，并明确冲突来源；不得覆盖03。
- F5：立即生效，但必须在同一次治理动作中同步检查01、02、03和Skill，避免长期存在冲突版本。

## 极简记录格式

06 的新建/合并记录只保留以下字段：

```text
裁决：不写入 / 合并 CAL-xxx / 新建 F1 / 修订03 / 本条经验
判断：一句可执行的“何时—做什么—为什么”。
证据：视频名 + 关键反馈或时间码。
适用范围与例外：各一句；不明确则不升级。
关联：03条目、CAL编号或本条日志路径。
状态：F1 / F2 / F3 / F4 / F5 / REVIEW。
```

完整逐视频过程保留在本条日志，不复制进06。

## 完成标准

- MAX 入口、06 和 Skill 都明确要求“先检索、后裁决、再写入”。
- 03、06、Skill 和单条日志各自只有一种职责。
- 每次长期知识写入都可看到裁决摘要和关联来源。
- 不产生新的平行规则库、重复规则或无证据升级。
