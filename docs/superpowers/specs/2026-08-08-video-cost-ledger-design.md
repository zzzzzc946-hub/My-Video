# MAX 视频成本台账设计

## 目标

让每条 MAX 视频从启动到交付都有可审计的 Token 与时间成本记录，并可计算“每分钟最终成片 Token 成本”，不依赖猜测或手工补数。

## 边界与权威

- 每条视频任务启动时创建一个 Token Budget 为 **40,000** 的 Goal；用户可在启动时明确覆盖预算。
- Goal 是预算、实际 Token Usage 与任务状态的唯一权威。没有从 Goal 获得的数据必须写“未采集”，不得估算。
- 每条视频在 `制作记录/<视频名>/cost-ledger.md` 保留独立成本卡；`rough-cut-log.md` 只链接成本卡或复制最终摘要，不重复维护两份明细。
- 只在真实交付完成后关闭 Goal 并写入最终数据；停止、取消或未交付任务标记“未交付”，不计算每分钟成片成本。
- 不新增工作台数据库、自动计时服务或跨视频聚合表。

## 数据流

1. 启动：创建 Goal，记录视频名、Goal ID、预算、启动时间、选定工具与初始状态。
2. 进行：每次真实发起转写或渲染时累加一次；用户输入、人工确认、素材等待或外部处理等待时记录开始/结束时间并累计人工等待。
3. 返工：进入已交付候选后的每次实际修改循环计为一次返工；内部首次 QA 修复不计返工。
4. 交付：从 Goal 读取实际 Token Usage，计算制作总耗时、人工等待、净制作耗时、转写次数、渲染次数、返工次数和最终成片时长。
5. 复盘：仅在 Goal 已完成、最终时长大于零且 Token 已采集时，计算 `实际 Token Usage ÷ 最终成片分钟`；否则显示“不可计算”。

## 成本卡字段

```text
视频名 / Goal ID / 预算 Token / Goal 状态
启动时间 / 交付时间 / 制作总耗时 / 人工等待时间 / 净制作耗时
转写次数 / 渲染次数 / 返工次数
最终成片时长 / 实际 Token Usage / 每分钟成片 Token 成本
数据完整性 / 例外说明 / 与 rough-cut-log 的链接
```

## 验收

- MAX Skill 的固定启动顺序包含创建预算 Goal 和成本卡。
- 交付流程包含读取实际 Usage、完成 Goal、填写成本卡和条件性成本计算。
- 模板明确定义各计数口径、等待时间和未交付规则。
- 不生成或修改任何具体视频、Goal、渲染、转写或工作台数据。
