# MAX × VideoUse 本地优先同步设计

## 目标

将两台电脑的日常工作切换为本地读写，GitHub 负责项目文本版本，NAS 只承担阶段镜像和媒体备份，避免 NAS 实时读写、双端覆盖和规则分叉。

## 权威与目录

| 内容 | 日常工作真源 | 同步目标 | 规则 |
| --- | --- | --- | --- |
| MAX 00–07 规则 | 当前工作电脑本地 `CHEN BRAIN` | NAS `CHEN BRAIN` | 同一时刻仅决策中枢可修改；切机前完成同步。 |
| Skill、项目文档、模板、代码 | Git 分支 `codex/two-computer-sync` | GitHub 私有仓库 | 两台电脑先拉取后编辑，编辑完成必须提交推送。 |
| 原片与交付 | 当前工作电脑本地 `MAX视频本地资料` | NAS 媒体／交付目录 | 每条视频只允许一台电脑编辑；不同步缓存与代理。 |
| 缓存、代理、`node_modules`、`.env` | 当前电脑 | 无 | 不进入 Git 或 NAS。 |

本机本地媒体根目录固定为：

- `/Users/chen.zip/Documents/Codex/MAX视频本地资料/原片`
- `/Users/chen.zip/Documents/Codex/MAX视频本地资料/交付`

## 同步协议

仅在用户明确说“同步配置和规则到 NAS”、规则确认后或切换电脑前执行。

1. 检查本地、NAS 和 Git 分支状态。
2. 对规则和配置逐文件比较。
3. 只有一端变更时，向另一端复制；两端均变更同一文件时停止并标记 `REVIEW`，由决策中枢合并后再同步。
4. 媒体和交付按视频项目目录同步；不覆盖原片、EDL、历史交付、缓存或代理。
5. 完成后记录同步范围、时间和异常；未完成同步不得切换同一视频的编辑电脑。

## 故障防护

- 第二台电脑先 `git pull origin codex/two-computer-sync`，再同步其本地知识库和媒体副本；不得把 `main` 当作工作分支。
- 两台电脑不得同时编辑同一视频、同一规则文件或同一工作台草稿。
- 旧文档中“NAS 挂载知识库为实时工作源”的描述全部改为“本地工作副本、NAS 阶段镜像”。
- 没有可用 NAS 或发现冲突时，继续在本地工作并停止同步；不得用单端覆盖另一端。

## 验收

- `config/nas-paths.json` 指向本地知识库、原片和交付目录。
- 双机文档明确本地优先、固定 Git 分支、冲突停写和切机闸门。
- README 与配置说明不再把 NAS 描述为实时知识库。
- 变更范围不含素材、EDL、缓存、交付片、密钥或 `.env`。
