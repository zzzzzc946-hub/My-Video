# MAX 视频项目 SOP 设计规格

## 目标

为 MAX 视频包装建立一套可重复执行、可检查、可持续校准的制作流程。流程从接收粗剪和制作资料开始，到 Remotion 包装、预览、渲染、交付与复盘结束。

SOP 只负责 MAX 视频包装，不承接选题、脚本创作、封面生成、发布运营或数据监控。

## 已确认方案

采用“一个主 SOP + 四个轻量模板”的结构：

1. 主 SOP 说明完整生产流程、阶段门槛、角色边界和异常处理。
2. 制作需求单统一每条视频的输入信息。
3. 时间线装配表把口播、画面、素材、动效和音效对齐到时间码。
4. 交付检查表约束 Studio 预览、静帧检查、完整渲染与成片验收。
5. 技术错题集记录可复现的制作和渲染问题，与品牌校准记录分离。

暂不把文字、字幕、动画、转场、音频和布局拆成独立 Agent 或独立 Skill。经过多条真实视频验证后，才考虑把稳定能力升级为 MAX 专属 Skill。

## 文件结构与职责

### `docs/MAX视频制作SOP.md`

主流程文件，包含：

- 项目边界和开始条件
- 阶段 0：资料接收与制作条件确认
- 阶段 1：粗剪验收与时间线拆解
- 阶段 2：包装方案与素材计划
- 阶段 3：Remotion 制作
- 阶段 4：Studio 预览与关键静帧检查
- 阶段 5：完整渲染与交付验收
- 阶段 6：反馈分类与经验回写
- 阻塞条件、返工规则和完成定义

主 SOP 只描述稳定流程，不重复品牌视觉细节和单条视频参数。

### `templates/制作需求单.md`

每条视频开工前填写，记录：

- 平台、比例、分辨率、帧率、目标时长和交付格式
- 脚本、粗剪、字幕、素材和品牌资源的实际位置
- 包装目标、包装强度、参考案例和明确禁用项
- 人脸区、字幕区、Logo 区和其他安全区要求
- 音频、字体、素材版权与缺失项状态

未确认的内容必须标为“未提供”或“未校准”，不得由 Codex 猜测补全。

### `templates/时间线装配表.md`

每个需要包装的片段占一行，字段包括：

- 起止时间码
- 对应口播或信息点
- 片段目的
- 画面形式
- 素材来源与文件名
- 动效与转场
- 字幕或屏幕文字
- 音效与音乐处理
- 安全区与遮挡检查
- 制作状态和备注

装配表是口播与包装之间的交接合同。没有时间码或内容目的的片段，不直接进入动效制作。

### `templates/交付检查表.md`

检查分为四组：

1. 内容对齐：画面、文字、素材和音效与口播一致。
2. 视觉安全：人脸、字幕、Logo、边缘和关键素材不被遮挡或裁切。
3. 技术正确：无黑帧、黑边、闪屏、缺帧、字体丢失、资源路径错误和渲染差异。
4. 交付规格：比例、分辨率、帧率、时长、编码、文件名和输出位置符合需求单。

只有完成 Studio 完整时间线预览、代表性关键静帧检查和最终成片渲染，才能标记为完成。

### `iteration/technical-errata.md`

只记录可以复现、可以验证的技术问题，使用固定字段：

- 日期和问题名称
- 发生项目与时间码
- 现象
- 根因
- 修复方式
- 防复发检查
- 影响文件或组件
- 是否已验证

一次性审美偏好不能写入技术错题集。MAX 品牌判断仍写入 `references/max-video-profile.md` 或 `iteration/calibration-log.md`，并且必须来自用户明确确认。

## 制作数据流

```text
用户提供资料
  -> 制作需求单
  -> 粗剪和时间线拆解
  -> 时间线装配表
  -> 素材进入 public/
  -> Remotion 帧驱动制作
  -> Studio 时间线和关键帧预览
  -> 静帧检查
  -> 完整成片渲染
  -> 交付检查表
  -> 用户反馈分类
      -> 单条视频修改
      -> 技术错题集
      -> 用户确认后的品牌校准
```

## 规则分层

### 通用技术规则

来自项目的 Remotion Best Practices，包括帧驱动动画、`public/` 素材管理、`staticFile()` 引用、Studio 预览和渲染验证。

### MAX 长期品牌规则

只保存被真实成片和用户反馈确认的视觉、字幕、动画、转场与音频规律。未确认项保持“未校准”。

### 单条视频参数

保存在制作需求单和时间线装配表中，不自动升级为长期规则。

### 技术错误

保存在技术错题集中。只有根因明确且修复已经验证的问题才写入。

## 阻塞与异常处理

以下情况停止进入制作阶段，并在需求单中写明缺失项：

- 未确认平台、比例、目标时长或交付格式
- 缺少脚本、粗剪或必要素材
- 素材无法读取或版权状态不明
- 参考方向与 MAX 已确认禁用规则冲突
- 用户要求修改只读 MAX 源文档但未明确授权

以下情况返回对应阶段，不继续交付：

- 口播与包装时间码错位：返回时间线装配
- 素材缺失或错误：返回素材计划
- 视觉遮挡或字幕冲突：返回 Remotion 制作
- Studio 与渲染结果不一致：进入技术排查并记录可复现证据
- 成片规格不符：重新渲染并重新执行交付检查

## 验收标准

SOP 落地完成必须满足：

- 五个目标文件存在且互相链接
- README 提供主 SOP 和四个模板的入口
- AGENTS 保留现有边界，只增加开工与交付时使用 SOP 的入口
- 模板中的字段足以支持一条真实视频从接收到交付
- 品牌校准、单条偏好和技术错误有明确分流
- 文档不包含未经确认的 MAX 风格规则
- 文档不要求 CSS transition、CSS animation 或 Tailwind animation
- 文档明确素材通过 `public/` 和 `staticFile()` 管理

## 暂不包含

- 选题日报、脚本生成和深度研究
- 封面生成与多比例封面适配
- 发布、评论区管理和数据监控
- 自动下载来源不明的网络素材
- 自动将每次反馈写入长期品牌规则
- 拆分独立 Agent 或创建多个 MAX Skill
