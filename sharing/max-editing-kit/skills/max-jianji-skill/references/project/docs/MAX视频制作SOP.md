# MAX 视频制作 SOP

## 目的

这套 SOP 用于把 MAX 视频包装做成可重复执行、可检查、可持续校准的生产流程。它从接收粗剪和制作资料开始，到 Remotion 包装、预览、渲染、交付与复盘结束。

本项目只负责视频包装，不负责选题、脚本创作、封面生成、发布运营或数据监控。

## 固定边界

- `02｜MAX顶层思维系统` 及其他 MAX 源文档只读，除非用户明确授权修改。
- 未经真实成片或用户反馈确认的 MAX 风格保持“未校准”，不得根据参考视频猜测补写。
- 文字、字幕、动画、转场、音频和布局属于本项目内部能力，不拆分独立 Agent。
- 所有项目素材进入 `public/`，Remotion 代码通过 `staticFile()` 引用。
- 所有动画由帧驱动，使用 `useCurrentFrame()`、`interpolate()` 或其他确定性帧计算。
- 禁止依赖 CSS transition、CSS animation 或 Tailwind animation。
- 参考视频用于理解信息组织和制作方法，不自动成为 MAX 品牌规则。

## 角色分工

### 用户

- 提供或确认脚本、粗剪、素材、平台和交付规格。
- 对包装方向、成片效果和 MAX 长期规则作最终判断。
- 明确哪些反馈只适用于当前视频，哪些可以继续验证为长期经验。

### Codex

- 检查输入是否满足开工条件。
- 把口播、画面、素材、动效和音效对齐到时间线。
- 使用 Remotion 完成帧驱动包装并保留可编辑结构。
- 预览关键帧和完整时间线，渲染静帧与成片并提供验证证据。
- 把反馈分流到单条修改、技术错题、组件参数或用户确认后的品牌校准。

## 核心文件

- [制作需求单](../templates/制作需求单.md)：每条视频开工前填写。
- [时间线装配表](../templates/时间线装配表.md)：制作前完成片段拆解。
- [交付检查表](../templates/交付检查表.md)：交付前逐项验证。
- [MAX 视频包装档案](../references/max-video-profile.md)：只保存已确认的长期品牌规则。
- [包装校准记录](../iteration/calibration-log.md)：保存用户明确确认的校准结论。
- [技术错题集](../iteration/technical-errata.md)：保存根因明确且修复已验证的技术问题。

## 状态定义

每条视频只使用以下状态：

1. `待补资料`：开工条件不完整。
2. `待装配`：资料齐全，尚未完成时间线装配表。
3. `制作中`：正在进行素材整理或 Remotion 包装。
4. `待检查`：制作完成，尚未完成完整验证。
5. `待确认`：已通过内部检查，等待用户确认。
6. `返工中`：用户反馈或验证失败，正在修改。
7. `已交付`：成片和交付记录完整。

## 阶段 0：资料接收与开工确认

### 输入

- 平台、比例、分辨率、帧率、目标时长和交付格式。
- 脚本、粗剪、字幕或逐字稿。
- 图片、视频、Logo、字体、音乐和音效等已有素材。
- 包装目标、参考案例、包装强度和明确禁用项。

### 动作

1. 复制[制作需求单](../templates/制作需求单.md)，为当前视频创建独立记录。
2. 核对所有文件的实际路径、格式和可读取状态。
3. 读取 `references/max-video-profile.md` 和 `iteration/calibration-log.md`。
4. 把缺失内容标为“未提供”，把尚无品牌结论的内容标为“未校准”。
5. 检查参考方向是否与已确认禁用规则冲突。

### 输出

- 一份填写完成的制作需求单。
- 明确的缺失项列表或“可以开工”结论。

### 通过条件

平台、比例、目标时长、脚本或粗剪、必要素材和交付格式全部明确。任何一项缺失，状态保持 `待补资料`，不进入阶段 1。

## 阶段 1：粗剪验收与时间线拆解

### 输入

- 已通过阶段 0 的制作需求单。
- 可播放的粗剪文件。
- 与粗剪版本对应的脚本、字幕或逐字稿。

### 动作

1. 检查粗剪时长、画面比例、音画同步和是否存在损坏片段。
2. 按信息目的拆分时间段，例如开场钩子、概念解释、证据展示、转折、总结和结尾。
3. 标记必须保留真人、需要全屏素材、需要重点文字或不需要包装的片段。
4. 在[时间线装配表](../templates/时间线装配表.md)中填写起止时间码、口播和片段目的。

### 输出

- 已完成内容拆解的时间线装配表。
- 粗剪问题清单；如果没有问题，明确记录“粗剪通过”。

### 通过条件

每个准备包装的片段都有明确的起止时间码和内容目的。口播版本与粗剪不一致时，返回用户确认版本，不进入阶段 2。

## 阶段 2：包装方案与素材计划

### 输入

- 已完成内容拆解的时间线装配表。
- 制作需求单中的包装目标和参考案例。
- 已确认的 MAX 品牌规则与禁用项。

### 动作

1. 为每个片段选择画面形式：真人主画面、全屏素材、人物画中画、标题卡、信息卡、图表、对比、屏幕演示或留白。
2. 为每个片段填写素材文件名、来源、使用范围和版权状态。
3. 设计动效、转场、字幕或屏幕文字和音频处理，但不虚构未校准的 MAX 风格。
4. 检查人脸区、字幕区、Logo 区和平台裁切安全区是否冲突。
5. 确定代表性检查帧：开场、信息最密集处、复杂转场、字幕与人物同时出现处和结尾。

### 输出

- 填写完整的时间线装配表。
- 素材清单和缺失素材列表。
- 代表性检查帧列表。

### 通过条件

每个包装片段都有画面形式、素材、文字、动效、音频和安全区处理。素材缺失或版权状态不明时，返回阶段 0 补充，不进入阶段 3。

## 阶段 3：Remotion 制作

### 输入

- 已通过阶段 2 的时间线装配表。
- 已放入 `public/` 的全部项目素材。
- 当前项目的 Remotion Best Practices。

### 动作

1. 使用 `staticFile()` 引用 `public/` 中的素材，不写脆弱的本机绝对路径。
2. 按内容责任拆分 Composition、Sequence 和可复用组件，保持时间线名称可读。
3. 使用帧驱动方式实现入场、强调、停留、退场和转场。
4. 保留安全区，避免人脸、字幕、Logo 和关键信息相互遮挡。
5. 控制动效密度和音效强度，避免每个片段都使用重动效或 `impact-heavy` 音效。
6. 每完成一个片段，更新装配表状态并记录实际实现与方案差异。

### 输出

- 可在 Remotion Studio 中打开的完整时间线。
- 与实际代码一致的时间线装配表。

### 通过条件

代码通过 `npm run lint`，全部本地素材可加载，时间线没有已知缺段、资源错误或非帧驱动动画，方可进入阶段 4。

## 阶段 4：Studio 预览与关键静帧检查

### 输入

- 可运行的 Remotion Composition。
- 阶段 2 确定的代表性检查帧。

### 动作

1. 在 Remotion Studio 中预览完整时间线，不只查看局部片段。
2. 检查口播、画面、字幕、动效和音效的时间对齐。
3. 渲染代表性静帧，检查布局、裁切、清晰度、安全区和信息层级。
4. 检查开场和结尾，以及所有复杂转场的前、中、后三个状态。
5. 把发现的问题写回装配表；可复现技术问题保留现象和证据，但尚未验证根因时不写入技术错题集。

### 输出

- 完整时间线预览结论。
- 代表性静帧文件和检查记录。
- 已修复或明确列出的待修问题。

### 通过条件

完整时间线已播放检查，代表性静帧全部通过，口播与包装无已知错位，人脸与字幕无冲突，方可进入阶段 5。

## 阶段 5：完整渲染与交付验收

### 输入

- 已通过阶段 4 的 Composition。
- 制作需求单中的最终交付规格。
- [交付检查表](../templates/交付检查表.md)。

### 动作

1. 按最终比例、分辨率、帧率和编码要求执行完整成片渲染。
2. 播放最终文件，检查黑帧、黑边、闪屏、缺帧、字体丢失、资源缺失和音画不同步。
3. 检查人声、背景音乐和音效层级，避免爆音、削波和重音效连续堆叠。
4. 核对文件名、时长、输出位置、文件大小和可播放状态。
5. 逐项完成交付检查表，记录验证文件和检查时间。

### 输出

- 最终成片文件。
- 填写完成的交付检查表。
- 交付说明和已知限制；没有已知限制时明确记录“无”。

### 通过条件

必须同时完成完整成片渲染、最终文件播放检查和交付检查表。只完成 Studio 预览或短片段渲染不能标记为 `已交付`。

## 阶段 6：反馈分类与经验回写

### 输入

- 用户对成片的原始反馈。
- 最终交付文件、需求单、装配表和交付检查表。
- 制作过程中的问题证据。

### 动作

把反馈分为四类：

1. **单条视频修改**：只影响当前成片，修改后更新装配表和交付检查表。
2. **技术错题**：问题可以复现、根因明确、修复已验证，写入 `iteration/technical-errata.md`。
3. **组件参数经验**：同一实现经过多次验证后，固化为项目内部组件默认值或可选参数。
4. **品牌校准**：只有用户明确确认的长期结论，才写入 `iteration/calibration-log.md`；稳定后再同步到 `references/max-video-profile.md`。

### 输出

- 已完成的返工，或明确的“无需返工”结论。
- 正确分流的复盘记录。

### 通过条件

所有反馈都有明确去向，没有把一次性偏好自动升级为长期规则，也没有把未验证推测写入技术错题集。

## 阻塞条件

出现以下任一情况，停止推进并报告具体缺失或冲突：

- 平台、比例、目标时长或交付格式未确认。
- 脚本、粗剪或必要素材缺失。
- 粗剪与脚本版本不一致。
- 素材无法读取或版权状态不明。
- 参考方向与已确认的 MAX 禁用规则冲突。
- 用户要求修改只读 MAX 源文档但未明确授权。

## 返工路径

- 口播与包装时间码错位：返回阶段 1 或阶段 2。
- 素材错误、缺失或来源不明：返回阶段 0 或阶段 2。
- 人脸、字幕、Logo 或安全区冲突：返回阶段 3。
- Studio 与最终渲染结果不一致：返回阶段 3 排查，并保留可复现证据。
- 输出规格错误：返回阶段 5 重新渲染并完整复检。
- 用户提出新的长期风格判断：先作为校准候选，按阶段 6 处理。

## 完成定义

一条 MAX 视频只有同时满足以下条件才算完成：

- 制作需求单、时间线装配表和交付检查表均已填写。
- 项目素材通过 `public/` 和 `staticFile()` 管理。
- 动画全部由帧驱动。
- Remotion Studio 完整时间线已经预览。
- 代表性关键静帧已经渲染并检查。
- 最终成片已经完整渲染并从头到尾播放检查。
- 文件规格与制作需求单一致。
- 用户反馈已经完成分类和回写判断。
- 没有未经确认的 MAX 风格被写入长期规则。
