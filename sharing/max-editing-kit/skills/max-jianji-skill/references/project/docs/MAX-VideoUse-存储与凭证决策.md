# MAX × VideoUse：存储与凭证决策

## 适用范围

本决策适用于本机未来所有 MAX 单条视频粗剪窗口。通用流程与工具选择以 [MAX 剪辑工作流与工具路由](MAX-剪辑工作流与工具路由.md) 为准；本文件只保留 VideoUse 的条件性凭证与存储约束。

## 共享转写凭证

- 共享配置唯一位置：`assets/video-use/.env`。
- 该文件由 VideoUse 的 `transcribe.py` 自动读取；新窗口不需要重新配置或粘贴 Key。
- Key 不进入项目仓库、单条视频工作区、剪辑报告、终端输出或聊天记录。
- 只有共享配置缺失，或工具明确报告 Key 不存在时，才需要重新配置。额度、网络或服务错误应按原错误处理，不重复索要 Key。

## 默认剪辑执行路由

- **默认：VideoUse。** MAX 口播的日常粗剪优先本地完成，产出可复现的转写、剪辑决策、EDL、预览和过程记录。
- **判断：Codex。** 新窗口先按 CHEN BRAIN 的 MAX 规则与任务卡理解素材，产出可审阅的结构策略、剪辑决策和时间码；VideoUse 只执行这些决定。
- **备选：ChatCut。** 仅当用户明确选择其可见时间线、协作或云端 Agent 时使用；使用前说明可能的积分消耗，避免不必要的视频、配音、音乐、图片和动效生成。

## 存储留存策略

- 每条视频完成时检查一次 `制作记录/` 下所有执行工具的可重建草稿占用；达到 **10GB** 才提醒。没有完成新视频时，不做定期检查。
- 提醒只提供清理清单，不执行删除。
- 长期保留：剪辑决策、EDL、粗剪后逐字稿、版本清单、反馈、项目记录和任务卡。
- 可按需清理：预览/中间 MP4、分段缓存、检查图、原始转写 JSON 和 `takes_packed.md`。
- 原片仍存在时默认不清理；原片已删除时，先确认最终交付是否另有备份，再由用户确认删除可重建草稿。最终交付片不在默认清理范围。

## 手动清理顺序

1. 确认原始素材是否仍保留，以及最终交付片是否已备份。
2. 先查看每个 `video-use/` 目录占用，找出最大的预览和分段缓存。
3. 用户确认后，只清理可重建草稿；过程文档保持不动。
4. 清理后记录删除了什么、释放了多少空间、原片状态如何。
