# MAX 粗剪 Skill

这是 MAX 真人口播的粗剪规则。目标不是机械删空白，而是让观点更早出现、逻辑更连贯、表达更干净，同时不改变原话的事实、立场或因果关系。

## 规则层级

- **已确认规则**：用户明确要求作为 MAX 粗剪能力执行的规则，写入本 Skill。
- **本条判断**：只写入该视频的 `rough-cut-log.md`，不外推。
- **待补输入**：个人知识库路径、账号数据、平台规格或某条视频的临时偏好，缺失时明确记录，不靠猜测补全。

用户对本 Skill 的明确修改，先更新本文件，再继续后续剪辑；不要把一次成片的审美偏好擅自升级为长期规则。

## 交付边界

- 处理范围：内容重构粗剪与表达精修。
- 不处理：字幕、音乐、特效、调色、转场、包装、配音或发布运营。
- 不覆盖原片。所有过程文档归档到 `制作记录/<视频名>/`；执行工具产生的缓存、预览和中间文件放在其具名子目录，不能写到桌面。

## 工具无关的执行路由

- MAX 粗剪流程与执行工具解耦：规则读取、素材理解、结构判断、确认、可审阅决策、质量检查、反馈校准和留存，对 ChatCut、VideoUse 或未来任何剪辑工具都相同。
- 每条视频在任务开始时明确选定一个执行工具。**不得启动未被选定工具**的转写、渲染、缓存或导出流程；工具切换必须先说明原因，并保留已有过程文档。
- **默认执行工具：VideoUse。** 它用于低成本、本地可复现的转写、EDL、预览与技术检查。只有用户明确选择 ChatCut（例如需要其可见时间线或云端 Agent）时才选 ChatCut；未来工具按同一选择规则接入。
- 只有选定 VideoUse 时，才使用 `/Users/chen.zip/.codex/skills/video-use/.env` 中的共享 `ELEVENLABS_API_KEY`，并显式传入项目内工作目录。配置存在时直接调用；不得要求用户重复粘贴 Key，也不得把 Key 写入项目、工作区、日志或聊天。

## 固定启动口令与首步顺序

当用户在本项目的新窗口放入视频并说“**用 MAX 剪辑工作流做粗剪**”（或意思等同的表述）时，必须先加载 MAX 粗剪 Skill，不能直接调用任何剪辑工具。

固定顺序如下：

1. 读取 `docs/视频项目剪辑上层Agent-理解文档.md`。
2. 在本机 `CHEN BRAIN` 工作副本先执行 `git pull --ff-only`；读取 `git rev-parse HEAD` 并记入本条任务卡，再读取 `/Users/chen.zip/Documents/CHEN BRAIN/03｜CHEN操盘手系统/03｜MAX剪辑系统/00｜MAX剪辑系统入口与读取顺序.md`，严格按其路由读取本条所需 MAX 规则。
3. 创建本条 **Goal**，默认 `token_budget: 40000`；记录 Goal ID、预算和启动时间。用户在启动时明确给出预算时，以其数值覆盖默认值。
4. 复制 `templates/视频成本台账.md` 到 `制作记录/<视频名>/cost-ledger.md`，写入视频名称、任务目录、Goal ID、预算、启动时间和选定工具。
5. 读取或创建本条任务卡，明确目标、临时约束和待确认项。
6. 明确本条执行工具；用户未指定时默认选 VideoUse。用户指定 ChatCut 或其他工具时，按指定工具执行，不启动 VideoUse。

每一条新视频都从此顺序重新开始；可以复用已确认的 MAX 规则，但不能跳过规则路由或把上条视频的临时偏好当作长期规则。当前窗口不是具体视频任务时，不创建 Goal。

## 草稿留存

- 过程文档是长期记忆：保留 `project.md`、`rough-cut-log.md`、`rough_cut_decisions*.md`、`edl*.json`、`post_cut_transcript*.md`、`manifest*.json` 与用户反馈。
- 可重建草稿包括执行工具产生的预览、渲染缓存、分段文件、检查图、转写缓存与临时素材。每条视频完成时统计一次 `制作记录/` 内这类内容的累计占用；达到 **10GB** 时提醒用户手动清理并先确认原片与最终交付片去留。没有完成新视频时，不做定期检查。
- 不得自动删除。原片仍在时默认不建议清理；原片已删除时，用户确认后才清理可重建草稿。默认不删除最终交付片。

## 默认交付标准

- 用户委托“剪这条视频”时，默认目标是一次性交付经过内部充分审核的**最终交付候选**，而不是把未经完成自审的版本命名为“第一版粗剪”交给用户逐轮校对。
- 剪辑师必须在交付前自行完成至少三轮独立检查：
  1. **结构审查**：逐段确认钩子、结论、论证、案例与收束的逻辑闭环，不为压时长整段删除关键上下文。
  2. **切点审查**：对每一个实际切口核验语义、口型、手势与姿态、呼吸与音频、画面切入五个维度；不自然时自行调整 EDL 并重新检查。
  3. **成片审查**：完整播放最终候选，并检查开头、中段关键转折、全部切点、结尾、音画同步、帧率、方向、时长和可播放性。
- 用户只需要为创作取舍、事实判断或其主观偏好提供反馈；明显的逻辑断裂、嘴瓢、重复、长静音、突兀跳切和技术问题应由剪辑师在首次交付前主动发现并修复。
- “预览”仅是内部可回退与验证产物，不得作为降低交付标准的理由。面向用户的首次文件命名为“最终交付候选”；用户确认后可重命名为最终交付。
- 最终候选通过文件和切点检查后，必须立即向用户交付可播放文件与 EDL；工作台启动、归档和同步在交付后进行，不能扣住已经验证的成片。工作台启动超过 60 秒时，报告其状态并继续交付，不等待它完成。
- 所有面向 MAX 审看的粗剪、复核、版本对比和最终候选文件，固定输出为 **1080P、30 fps**（竖屏为 `1080×1920`）；不得按源帧率或设备自动选择。原片、原始 EDL 和最终母版不因此改变；只有 MAX 明确要求指定母版规格时才另行输出。

## 快速粗剪通道

以下条件同时满足时，优先走快速粗剪通道：单一源视频、只做删留或调序、无字幕、无调色、无 B-roll／贴纸／覆盖层／包装、输出为固定审片规格。

- 源片位于 NAS 时，先复制到本机 `mediaRoot` 的本条视频目录并核对文件大小或指纹；后续转写、画面检查和渲染只读取本地副本，不改动 NAS 原片。
- 内容判断、逐字稿、词级切点、EDL、30ms 音频淡入淡出和五维切点审查与常规粗剪完全相同；快速只改变编码与交付顺序，不降低剪辑精度。
- 快速候选固定输出竖屏 `1080×1920`、30 fps、H.264 硬件编码（`h264_videotoolbox`），并且必须使用与最终母版相同的 EDL。可为审片重新采样到 30 fps，但不得改时间码或用关键帧粗截替代词级切点。
- 符合条件时，最终候选必须从本地 VideoUse 工作台的“审片版导出”发起，并选择 MP4、1080P、30 fps、标准质量；确认其显示快速导出／硬件编码后再执行。全局 `video-use/helpers/render.py` 仅可用于草稿或不符合快速条件的兼容回退，不得用于此通道的最终候选。
- 开头、结尾和每个实际切点仍从原片或高分辨率源帧抽检；通过后立即交付。原始分辨率母版只在用户明确要求时生成，并作为后台任务，不阻塞快速候选。
- 多源、HDR／需色彩管理、字幕、调色、外部素材、动画、复杂转场、非标准比例或用户明确要求原规格时，自动退出快速通道，回退到常规可审阅渲染流程。

## 全片分析与版本融合

- 长口播必须先完成“全片逐字稿 → 观点单元 → 主线与支撑关系”的分析，再落时间线；不能按原始时间顺序机械删句，也不能因为目标时长、条数或短视频惯例强行压缩。
- 存在用户版、内部审阅版或多个历史版本时，先比较观点完整度、上下文连续性和信息密度，明确各版优缺点与取舍；不以“更短”自动等同于“更好”。
- 版本融合以原片逐字稿和原始时间码为唯一内容依据；用户版或历史预览只能作为节奏、自然度和包装参考，不能作为下一版 EDL 母版。
- 合理时长由内容闭环和信息密度决定，不预设 5 分钟或固定秒数；只要新增时长承担必要上下文、机制、案例或情绪落点，就允许保留更长版本。
- 候选拆条必须同时满足独立观点、低重复、完整闭环、独立收益；与主片共享核心观点或关键论据的片段只作为内部审稿样片。
- 每个“保留／删除／压缩／调序”判断都记录原始时间码、逐字稿证据、论证单元、前后句完整性、语义风险，以及判断来自 MAX 规则还是本条编辑假设。

## 两阶段粗剪

### 1. 内容重构

先用词级逐字稿与必要画面检查，把口播拆成：钩子、核心结论、论证、例子、补充、行动引导。

- 找出最强、最独立且不依赖前文的观点，优先放在开头，尽早给出继续观看的理由。
- 可整段删除跑题、重复论证、低价值例子、过长铺垫或不推进主论点的内容。
- 可重新组织段落，使逻辑成为“钩子 → 结论/冲突 → 关键论证 → 必要例子 → 收束/行动”。每次调序必须在日志中写明原顺序、目标顺序和逻辑理由。
- 调序后仍须保持原话事实、时间关系、因果与立场；不能拼接出说话人未表达的结论，不能把依赖上下文的话孤立为误导性钩子。
- 除非本条涉及高风险调序、事实歧义、多个合理创作方向或用户明确要求先看方案，否则剪辑师在内部完成结构策略后直接生成 EDL 和裁切文件；首次面向用户的输出必须满足“默认交付标准”。

### 2. 表达精修

在已确认的结构内逐句清理：口误、错词后的重说、重复、无效气口、长静音、开头准备和结尾离场。

- 以逐字稿、时间码和画面作为依据；切点落在词边界，并留 30-200 ms 缓冲。
- 每个实际片段边界加 30 ms 音频淡入淡出，避免爆音。
- 保留正常思考停顿、完整句和情绪峰值。没有清晰依据时，保留并标记待用户确认。
- 不能靠剪辑“修正”没有替代表达的事实错误；可保留、删除整段，或请求用户提供重录/更正方案。

## 长期执行细则

### 先全局理解，再下时间线

- 先完整阅读词级逐字稿，分析观点、论证、案例、重复表达和可重组段落；不能沿原始时间线逐段机械删废话。
- 目标结构优先于拍摄顺序：`钩子 → 核心结论／冲突 → 必要论证 → 有效案例 → 收束`。
- 允许蒙太奇式调序，但不得改变原话事实、立场、时间关系或因果；每次调序必须记录原顺序、目标顺序、理由、语义风险和前后句校验。

### 五维切点审查

每个候选删改点都同时检查：语义、口型、手势与姿态、呼吸与音频、画面切入。文字冗余本身不是删词理由；单独删“而且是”“就是”等词前，必须确认删后句子节奏、口型、手势和呼吸自然。证据不足时保留并标记 `REVIEW`。

- 发现嘴瓢、口误、半句改口或重复起句时，优先删除完整错误片段及其无效气口；若只删单词会造成口型、手势或呼吸断裂，则扩大到最近自然词边界，必要时保留短暂思考停顿。
- 过渡段必须按“前一观点的落点 → 下一观点的起点”试听和看片，重点审查相邻概念之间是否突兀，不能只凭文字相似就硬切。

### 钩子与拆条

- 后段强结论只在脱离上下文仍完整、真实、可被正文自然接住时前置为钩子；否则使用原开头中最独立、最有冲突或收益感的表达。
- 不为数量 KPI 强拆长视频。每条候选拆条必须有独立中心观点、低论证／案例重合度、脱离其他条仍完整的理解闭环和足够独立价值；否则保留主片或降级为内部审稿样片。

### 交付候选、原片权威与 QA

- 内部先完成可审阅策略：建议时长区间、保留主线、整段删除、压缩、调序、原始时间码、理由、规则来源、编辑假设和语义风险。仅在存在高风险调序、事实歧义、多个合理创作方向或用户明确要求时，才在裁切前请求用户确认。
- 可编辑 EDL 必须直接引用原片与原始时间码；预览片、低清草稿和历史导出片只能作为审阅证据，不能成为下一版 EDL 的母版。
- 面向用户交付前必须完成默认交付标准的三轮内部审查；至少审查钩子独立性、每个切点的五维连续性、调序后的逻辑、结尾完整性、音画同步、方向、帧率、时长、可播放性，以及未清理的嘴瓢、口误、重复和明显拖沓。

## 留存与运营判断

粗剪以提升理解与留存为目标，而不是承诺爆火：

- 开头快速建立冲突、反常识、明确收益或高价值结论。
- 例子只保留能证明主张、推动理解或增加可信度的部分。
- 每一段都应回答“为什么观众要继续看”；没有贡献的内容优先删除或压缩。
- 用账号数据、历史案例和用户反馈校准判断；没有数据时把判断标为编辑假设。

- 用户确认、素材补充、外部授权或明确暂停期间，记录人工等待区间；`净制作耗时 = 制作总耗时 - 人工等待时间`。
- 首次“最终交付候选”之后，因用户反馈、验证失败或明确创作取舍进入的实际修改循环计一次返工；首次内部 QA 修复不计返工。
- 真实交付时，读取 Goal 实际 Token Usage，写入成本卡的交付时间、总耗时、人工等待、净耗时、转写次数、渲染次数、返工次数与最终成片时长。仅当 Goal 已完成、Usage 已采集且时长大于零时，计算 `实际 Token Usage ÷ (最终成片时长秒 ÷ 60)`。
- 写完交付成本卡后才将 Goal 标记为完成，并在交付说明中附成本摘要。任务取消、停止或未形成最终成片时，Goal 保持未完成或标记取消，成本卡标为“未交付”，不计算每分钟成片 Token 成本。

## 可审阅过程

1. 检查源片实际时长、方向、帧率、音画同步与可播放性。
2. 生成并缓存词级转写、可读逐字稿和关键画面检查图。
3. 在 `rough-cut-log.md` 记录每个候选：原始时间码、类型、依据、前后句完整性、调序原因、规则状态与待核验点。
4. 生成 EDL 和低清预览后，检查开场、每个切点、逻辑连接与结尾；记录实际删减和用户反馈。
5. 用户可按时间点要求保留、删除、前移、后移、重组或复原。所有版本可回退，不覆盖原片。
6. 用户明确说“开始精剪”前，停留在本 Skill 的范围；之后的字幕、包装与音频处理由独立流程承接。
